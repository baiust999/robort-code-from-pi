**Reading this table.** The simulated column uses the paper's own verified kinematic model (no-load speed, firmware ramp time) plus the already-measured command-latency distribution of Table 5.1, as a generous stand-in for total stop-command-to-halt delay -- it does not include human operator reaction time, which would only widen the simulated distribution somewhat, not close a ratio measured in the tens. The real/simulated ratio column shows that Table 5.4's tape-measured means remain far larger than even this generous model at every PWM level, which is the same CONTRADICTED finding the paper's own text states in prose; this table only gives it a concrete number per speed instead of one order-of-magnitude sentence.

**Limitations.** The PWM-to-speed scaling is a linear no-load DC motor assumption, not independently verified for this specific motor under its actual rolling load; the command-latency input is a real measured distribution (Table 5.1) but was measured for a different purpose (command/telemetry confirmation, not a stopping-distance proxy) and excludes human reaction time entirely. This simulation does not explain the real Table 5.4 anomaly and is not offered as doing so -- the paper's own three candidate explanations (procedure difference, motor/wheel spec mismatch, recording error) remain equally open. This file exists only to give the magnitude of the gap a number, for a reader who wants more than 'one to two orders of magnitude'.
